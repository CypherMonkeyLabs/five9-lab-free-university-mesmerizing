# Inbound campaigns

- Inbound is a running campaign plus a script. Busy means the campaign is not in the call. A DNIS answers only while the campaign runs An inbound campaign receives calls for a DNIS and processes them with that campaign&#x27;s IVR script. The inbound topic is blunt about state: if the campaign is not running, callers hear a busy signal. The script is the inbound product Once the campaign answers, the IVR script is the product the caller meets. The inbound topic lists custom greetings, loops and branching, collecting information, using contact data, voicemail when the queue is long, forward to a third party, and priority. Queue treatment is a choice, not a hope The inbound topic allows custom prompts and hold music, a message when agents are unavailable, voicemail, and a forward to a third party. Those are different exits. Hold music is not voicemail. A forward leaves your agents entirely. Priority and service level The inbound topic says you can prioritize inbound traffic. Skill Transfer has a Priority tab in the community write-up. Skill groups themselves have service-level settings in the basic admin topic. Schedules, not a stopped campaign The campaign admin tree includes IVR script schedules for autodial and inbound campaigns. The planning topic tells you to set the campaign IVR schedule after the script exists. A schedule swaps treatment by time. Stopping the campaign does not. Stopping it returns busy. Pause before the next call Skill Transfer has Pause Before Transfer, in seconds, on the General tab. The default is 0. A value above 0 waits that long after an agent is selected before the call is delivered, so a queue does not slap the next call down instantly. Inbound design review A review you can finish in one sitting: DNIS, running campaign, script, skill on the Outbound Skills tab, overflow module, schedule, and pause. Each one has a public page. None of them is a trunk setting.
